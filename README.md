# PyTrace · Python 运行可视化工作台

一个**完全本地运行**的单机应用：把任意 `.py` 文件丢进来，实时看到它运行时的
**函数调用、入参、返回值、逐行执行轨迹、import 行为和标准输出**——就像给代码做了一次"动态 CT 扫描"。

```
拖入 .py  →  子进程插桩运行  →  事件流实时推送  →  调用树 / 瀑布图 / 回放动画
```

---

## ✨ 功能

| 功能 | 说明 |
|---|---|
| 🎬 **执行舞台** | 页面中央按「输入 → 过程 → 输出」三块演示：输入块显示当前函数收到的实参；过程块逐帧演示变量的一生（新变量先以 <b>?</b> 出现，值飞入落定；<b>c = a + b</b> 会把 a、b 的值拉进算式算给你看）；输出块实时承接 print 结果。导入模块（📦 导入 math）、定义函数（形参 + 默认值逐个展示）都有专属动画，带亮暗对比，当前步骤高亮 |
| 💡 **新手说明卡片** | 舞台顶部实时显示"这一步在干什么"的人话解释：`if __name__ == "__main__"`（程序入口从这里开始执行）、`class RagService`（对象模板，包含哪些方法，`RagService()` 会自动执行 `__init__`）、import（导入了什么、怎么用）；**链式调用逐段拆解**——`res=RagService().chain.invoke("", config)` 会拆成「① 创建实例并执行 `__init__` → ② 取出属性 chain → ③ 调用 invoke 并传参 → ④ 结果赋给 res」，每步都能看到真实展开的调用事件 |
| 🎞 **动效编排 v7** | 教学卡片三行分层揭晓；结果揭晓带扫光；**条件真假 / 循环轮次徽标飞入**（✓True 绿 · ✗False 红 · 第 n 轮 蓝）；变量值**翻牌**（旧值上滑、新值顶入）；值落定冲击波（目标弹一下 + 光圈扩散）；运算符在操作数就位后脉冲点亮；栈帧从右侧推入；执行行切换时头部扫光。飞行元素有上限治理，系统「减少动态效果」时全部让路 |
| ⏱ **手动调速** | 舞台右上角可随时切换 0.5× ~ 3× 动画速度，选择会被记住 |
| 📞 **调用细节** | 所有函数调用都展示入参：`return round(s, 2)`、`s = circle_area(2)`、`logger.info(...)` 等会把参数值飞入算式；返回时函数名 + 返回值落定 |
| 🔥 **异常路径** | `raise` / `assert` 红色高亮展示异常类型与内容；try 块、异常抛出/传播（⚠ 类型 · 消息 · 行号）都有专属演出 |
| 🌊 **数据流动画** | 调用发生时参数值化作青色粒子从调用行**流入**函数体；返回时结果化作紫色粒子**流回**调用行，粒子带实参/返回值标签 |
| 🔍 **调用树 / 瀑布图** | 每个函数一行：函数名 + 实参摘要 + 时间条 + 耗时，按调用层级缩进，可展开/选中 |
| 📥 **入参 · 返回值 · 局部变量** | 点任意调用，右侧检查器显示该次调用的完整参数树、返回值树、返回时的局部变量 |
| ▶️ **时间轴回放** | 运行结束后可拖动进度条 / 播放 / 单步（← → 空格），代码区逐行高亮当前执行位置 |
| 🕘 **最近项目** | 打开过的文件夹 / 文件自动记录，顶栏「最近」一键恢复：目录按磁盘路径重扫（永远最新），小文件连内容一起记住 |
| ⏪ **变量时间旅行** | 变量卡片上点 ⟲：看这个值每一次变化（旧值→新值、哪一行），点任意一条回到那一刻 —— 回答「这个值什么时候被谁改的」 |
| 🔴 **断点调试** | 点顶栏「调试」开启：**在行号上点一下就是断点**（红点会记住，重开页面还在），再点运行——程序会**真的停在断点处**等你，而不是跑完才能回放。底部工具条：继续（F8）/ 单步跳过（F9）/ 单步进入（Shift+F9）/ 单步跳出（Alt+F9）/ 停止；运行中随时增删断点、立即生效不用重跑；暂停期间不计入超时。断点只对当前运行的入口文件生效（其他文件只记调用、不逐行追踪，不做假承诺） |
| 📦 **import 可视化** | 静态分析（AST）+ 运行时 hook 双视角：模块、耗时、来源路径、是否标准库 |
| 📊 **耗时统计** | 按函数聚合自身耗时排行、最慢单次调用 Top 8、事件数 / 调用数 / 最大深度 |
| 🖥 **输出台** | print / stderr / 异常实时输出，异常自动定位到源码行 |
| 🛡 **安全隔离** | 用户代码在**独立子进程**中执行：超时强制终止、事件总量上限、input 自动跳过 |
| 🧩 **依赖桩** | 本机没装 langchain / langgraph / pandas 之类的包也能跑：`import` 失败时自动换成占位对象，界面标注「未安装·占位」；被当装饰器用时（`@tool` 等）保留原函数体继续真实执行 |
| 🚧 **副作用护栏** | 默认拦截联网、越界写盘、启动子进程；过长 `sleep` 自动压缩——本地演示不会因一份陌生代码搞乱机器，每次拦截都有提示 |

| 📂 **多种打开方式** | 拖拽上传 / 打开文件 / **打开文件夹（整个项目，自动识别入口）** / 4 个内置示例，代码只在本机执行、不上传 |

## 🐍 用哪个 Python 跑你的代码（重要）

PyTrace 用**你自己的解释器**执行你的代码——你的代码在哪儿能跑，就在哪儿观测：

1. **自动检测**：启动时会列出本机候选（项目内 `.venv`、VS Code / PyCharm 配置的解释器、
   conda、PATH 上的 python），顶栏下拉可切换并记住；
2. **验证环境**：点「验证环境」用选中的解释器逐个检查代码里的 import，
   缺什么直接给出 `pip install` 命令；
3. **项目目录**：在顶栏填入项目在磁盘上的真实路径，代码就会在你的项目目录里
   **原地运行**——相对路径读文件、本地包 import、数据文件全部和你在 IDE 里跑时一样；
4. 探针 `runner.py` 只用标准库、兼容 Python 3.8+，所以它可以被**任何一个**解释器加载。

### 📡 更进一步：把探针装进你自己的进程

顶栏「**接入我的 IDE**」——不再把代码交给 PyTrace 跑，而是探针钻进你的进程：

```bash
# 方式一：命令行（推荐，带自动插桩，能看到条件真假 / 循环轮次 / 赋值结果）
python -m pytrace main.py            # 在 PyTrace 目录下执行；其它目录先加 PYTHONPATH

# 方式二：代码注入（在 IDE 里点运行就行，加在脚本最前面）
import sys; sys.path.insert(0, r"<PyTrace 所在目录>")
import pytrace; pytrace.attach()
```

- 用的是**你的解释器、你的工作目录、你的环境变量**，和你在 IDE 里点运行完全一致
- 终端输出完全保留：print 照常打印、异常时 traceback 与直接 `python main.py` 逐字一致
  （探针自己的帧会被裁掉，不会出现在栈里）
- 方式一默认以**脚本所在目录**为工作目录（相对路径、本地包导入都正常）；
  `--cwd 目录` 可指定，`--cwd-keep` 保持当前目录
- 缺包时终端直接提示缺的是哪个 —— 通常说明你 IDE 用的是另一个解释器，换它重跑即可
- 探针只旁观（settrace + import 记录 + stdout 转发），不装依赖桩、不装护栏——你的环境里一切都是真实的
- 事件仅写入本机 `~/.pytrace/live/`，由本机 PyTrace 服务读取；不上传、不联网
- 运行结束回到面板，再跑一次会自动开始新一轮演示

## 🏗 实现原理

```
┌──────────────┐   JSONL 事件文件   ┌──────────────┐   WebSocket   ┌──────────────┐
│  runner.py   │ ─────────────────> │   app.py     │ ────────────> │  浏览器前端   │
│  探针(子进程) │    边写边读        │  FastAPI 服务 │   实时推送     │  折叠+渲染+回放│
└──────────────┘                    └──────────────┘                └──────────────┘
```

1. **探针（runner.py，子进程）**
   - `sys.settrace` 采集 `call / line / return / exception` 四类事件；
   - `builtins.__import__` 钩子记录每次 import 的模块、耗时与来源文件；
   - **依赖桩（guard.py）**：import 失败时补占位模块，让缺包代码也能继续执行，并如实标注；
   - **副作用护栏（guard.py）**：拦截联网 / 越界写盘 / 子进程，压缩过长 sleep；
   - 重定向 stdout/stderr，`print` 实时变成事件；
   - 事件以 JSONL 追加写入临时文件，父进程**边写边读**，实现真正的"运行中可视化"。
   - 归属规则：用户文件的帧全量记录；标准库/三方库只展开"用户直接调用的一层"，
     内部深层调用丢弃，避免调用树被 `importlib`、`posixpath` 刷屏。

2. **服务（app.py）**
   - `/ws/run` WebSocket：spawn 子进程 → 轮询事件文件 → 逐条推送 → 结束时发统计；
   - **语义叠加**：按 (文件, 行号) 把 AST 静态分析出的"这行在做什么"挂到真实执行的行事件上——
     真实值与人话解释同时具备；
   - `/api/analyze`：AST 静态分析（导入清单、函数签名、类结构）；
   - `/api/simulate`：逻辑推演（兜底通道，不执行代码）；
   - 运行隔离：每轮运行独立临时目录，保留最近 24 轮，超时/手动停止都会强杀子进程。

3. **前端（原生 HTML/CSS/JS，无构建步骤）**
   - 事件折叠成 `span` 树模型 → 调用树 + 瀑布图 + 统计聚合；
   - 执行流可视化：SVG 光路 + 贝塞尔数据流粒子（入参流入 / 出参流回，带值标签、限流防爆量）；
   - 回放引擎：任意位置 `seek` 都会重建派生状态，播放按事件等速推进（1× ≈ 5 秒放完），
     代码区同步高亮"当前执行行"；
   - 手写 Python 语法高亮（逐 token 扫描，支持三引号跨行）。

## 📦 打包成独立桌面软件

```bash
# 方式一：原生窗口（体验最接近桌面软件）
pip install pywebview
python app.py --desktop

# 方式二：一键打包成单文件可执行程序（推荐，v2.5.0 起官方支持）
# Windows：双击 build_windows.bat，产物 dist\PyTrace.exe
# Linux / macOS：
python -m pip install pyinstaller
python -m PyInstaller --clean --noconfirm pytrace.spec   # 产物 dist/PyTrace
```

打包版说明（v2.5.0）：

- **双击即用**，无需安装 fastapi / uvicorn（已捆绑）；但**运行 PyTrace.exe 的机器仍需安装 Python**——
  产品定位就是"用你自己的解释器跑你自己的代码"，PyTrace 只观测、不代跑；
- `runner.py / guard.py / instrument.py / envcheck.py / interp.py` 以**源码**形式随包，
  由探测到的用户 Python 执行；找不到解释器时界面会给出明确指引而不是一条 spawn 报错；
- 运行历史（`runtime/`）落在 **exe 旁边的目录**（打包内的临时解压目录退出即清空，不能存东西）；
- 杀毒软件可能对"陌生单文件 exe"报警：把 exe 所在目录加入白名单即可（运行历史也在那里）。

## 🔒 安全与限制

- 用户代码在独立子进程运行，主服务不加载用户代码；
- 默认 10 秒超时（可调 1–120 秒），死循环会被强制终止；
- 单次运行事件上限 8 万条、源码上限 2MB，防止把浏览器打爆；
- `input()` 会收到 EOF 并提示（单机可视化模式无交互 stdin）；
- 仅绑定 `127.0.0.1`，不对外网开放；代码不会被上传到任何服务器。

## ❓ FAQ

- **为什么有的库调用只显示一层？** 为了性能与可读性，标准库/三方库只展开用户直接调用的那一层，
  打开"库调用"开关可以看到被记录的库调用。
- **我的代码有 `input()` 怎么办？** 会自动以 EOF 跳过并提示；如需交互输入，建议先把输入写死在代码里。
- **事件很多会不会卡？** 前端做了渲染节流与行数上限（2500 行树 / 1500 条事件流）；
  建议先用小规模数据跑通逻辑，再放大参数。
