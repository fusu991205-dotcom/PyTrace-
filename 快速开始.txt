PyTrace · Python 运行可视化工作台 —— 快速开始（v7）
=====================================================

这是什么？
----------
把你写的 Python 代码真实跑一遍，像"放动画"一样逐帧演示：
每个变量怎么诞生、值怎么变、函数收进什么参数、算出什么结果、
导入了哪些模块、print 出了什么、异常在哪一行抛出。
代码只在你自己的电脑上跑，不上传、不联网。

新增（本版）：
  · 动效增强：条件真假 / 循环第几轮 会以徽标飞进舞台，变量值变化有翻牌动画
  · 教学卡片：每一行都讲「做什么 / 为什么 / 结果」三件事
  · 接入我的 IDE：在你自己的进程里跑，PyTrace 只在旁边看（详见第四节）


一、第一次启动（三选一）
------------------------
【Windows】双击 start_windows.bat
  · 需要已装 Python 3.8+（python.org 下载，安装时勾选 Add Python to PATH）
  · 首次运行会自动装依赖 fastapi / uvicorn，需要联网一次

【macOS / Linux】终端里执行：  ./start.sh
  · 或直接：python3 app.py

【命令行参数】
  python3 app.py --file 你的脚本.py    启动时直接载入这个文件
  python3 app.py --port 9000           换端口（默认 8765，被占用会自动 +1）
  python3 app.py --no-browser          不自动打开浏览器
  python3 app.py --desktop             原生窗口（需先 pip install pywebview）

启动后浏览器自动打开 http://127.0.0.1:8765 。没打开就手动访问。


二、三步上手
------------
第 1 步：载入代码（任选一种）
  · 拖一个 .py 文件到窗口里
  · 点「打开文件」
  · 点「打开文件夹」选整个项目
      - 会自动识别入口（优先 `if __name__ == "__main__"` 的文件，其次 main.py）
      - 顶栏出现「入口」下拉，可切换从哪个文件开始
      - 左侧会显示文件树，点文件可切换查看，点 × 关闭文件
  · 顶栏「示例」下拉里有 4 个内置例子（默认不预载）

第 2 步：确认用哪个 Python 跑（重要）
  顶栏「解释器」下拉：自动列出本机的候选
      · 项目内的 .venv / venv
      · VS Code / PyCharm 里配置的解释器
      · conda 环境、PATH 上的 python
  顶栏「项目目录」：填你项目在磁盘上的真实路径（如 D:\work\myproj）
      · 填了就在你的项目目录里原地跑 —— 相对路径读文件、本地包 import、
        数据文件全部正常，和你在 IDE 里点运行一致
  顶栏「验证环境」：用选中的解释器逐个检查代码里的 import
      · 缺哪个包直接告诉你是哪个、给出对应的 pip install 命令

第 3 步：点右上角「运行」
  中间「执行舞台」按 输入 → 过程 → 输出 三块开始逐帧演示：
    · 输入块：当前函数收到的实参
    · 过程块：变量卡片 + 算式动画
        新变量先显示 `?`，值飞进来落定；
        `c = a + b` 会把 a、b 的值拉进算式，运算符点亮，结果飞进 c；
        变量值变化时旧值上滑、新值顶入（翻牌）
    · 输出块：print 的结果实时落进来
    · 舞台顶部教学卡片：第几行 + 做什么 / 为什么 / 结果
        结果会等真正执行到那一行才揭晓（条件真假、第几轮、算出多少）


三、动画怎么控制
----------------
· 舞台右上角「速度」：0.5× ~ 3×，随时可切，选择会被记住
· 「逐帧动画」复选框：关掉就只显示结果、不播动画（事件很多时更快）
· 条件真假（✓ True / ✗ False）、循环第几轮（第 n 轮）会以徽标飞进结果区
· 底部时间轴：⏮ ⏯ ⏭ 单步前进 / 回放，拖进度条可跳到任意时刻
· 系统开启"减少动态效果"时，PyTrace 会自动收敛动画


四、接入我的 IDE（推荐给"代码依赖复杂"的项目）
-----------------------------------------------
适合：你的项目有很多三方包、要靠 conda 环境、要用相对路径读数据、
      或者就是想 100% 复现你在 IDE 里点"运行"的那一次。
做法：不再把代码交给 PyTrace 跑，而是让探针钻进你自己的进程。

  点顶栏「接入我的 IDE」，面板里有两种方式，都能一键复制：

  方式一 · 命令行（推荐，带自动插桩，信息最全）
      在 PyTrace 目录下执行：
          python -m pytrace 你的脚本.py
      脚本参数照常跟后面：python -m pytrace main.py --debug 1
      不在 PyTrace 目录也行，把 PyTrace 目录加进 PYTHONPATH（面板里的
      复制命令已经按你的安装路径和当前文件名生成，直接粘就行）：
          Windows:    set PYTHONPATH=D:\soft\PyTrace && python -m pytrace main.py
          macOS/Linux: PYTHONPATH=/opt/PyTrace python -m pytrace main.py
      终端里会先打印几行 [pytrace] 信息（脚本 / 工作目录 / 会话号），
      然后你的 print 照常输出、报错时 traceback 和直接 python 运行一模一样；
      同时界面上开始逐帧演示。
      工作目录规则：默认按「脚本所在目录」运行（open("data.txt") 等相对
      路径都和你在项目里跑一致）。想换目录用 --cwd 目录；想保持当前目录
      用 --cwd-keep。
      缺包时终端会直接提示缺的是哪个包 —— 说明你 IDE 用的是另一个解释器，
      换成那个解释器（/路径/python -m pytrace main.py）再执行即可。

  方式二 · 代码注入（在 IDE 里直接点运行）
      在脚本最前面加两行（路径换成你的 PyTrace 目录）：
          import sys; sys.path.insert(0, r"D:\soft\PyTrace")
          import pytrace; pytrace.attach()
      然后照常 Run。从这行之后执行的所有代码都会被投到界面。

  框架回调文件（如 LangChain 的 middleware / 工具注册文件）特别说明：
    这类文件模块级只有 import 和函数定义，本身不会执行任何业务逻辑 ——
    普通运行只能看到「导入了什么」。PyTrace 会自动检测这种情况，
    用构造的演示入参把每个回调函数**真实调用**一遍：
      · 执行路径（try / if / 调用链 / 异常处理）全部真实，
        条件判断的真实值、每行算出的结果照常在舞台揭晓
      · 只有传入的值是演示数据，变量卡片会标注 ⟨演示:…⟩，界面有说明卡片
      · 被装饰器包装的函数优先取 __wrapped__（直接演示你写的原始函数体）
      · 在真实 Agent 里，这些函数由框架自动触发；演示只是让新手看到它的过程

  说明：
    · 用的是你的解释器、你的工作目录、你的环境变量，环境 100% 是你自己的
    · 探针只旁观（不装依赖桩、不拦截任何东西）
    · 事件只写到本机 ~/.pytrace/live/，由本机 PyTrace 读取
    · 一次运行结束后，再跑一次会自动开始新一轮演示
    · 方式二没有"条件真假/第几轮"这类插桩信息（代码已在跑，插不进去），
      想要这些用方式一


五、界面其它区域
----------------
· 左侧源码：当前执行行高亮，调用处与函数定义之间有一条流动的光带
· 右侧检查器：点调用树里任意一次调用，看完整入参/返回值/局部变量
· 底部面板：
    调用树   —— 每个函数一行：入参摘要 + 耗时条，按层级缩进
    导入     —— 导入了什么、耗时、标准库还是三方、是否你直接 import
    统计     —— 函数耗时排行、最慢单次调用 Top 8、事件数/深度
    输出     —— print / stderr / 异常，异常自动定位到源码行
    事件流   —— 原始事件流水（排查问题用）


六、发给别人用
--------------
把整个 PyTrace 文件夹（或 PyTrace-本地版.zip 解压后）发给对方：
  · Windows：双击 start_windows.bat
  · macOS/Linux：./start.sh
对方只需要有 Python 3.8+，首次启动联网装两个依赖即可。
对方本来能跑的代码，在他自己机器上就能跑（解释器可选、环境可验证）。


七、常见问题
------------
Q: 双击 bat 窗口一闪而过？
   没装 Python，或装的时候没勾 Add to PATH。装好 Python 3.8+ 再试。

Q: 运行报 "No module named xxx"？
   点「验证环境」，它会用你选中的解释器告诉你缺哪个包、该执行哪条 pip 命令；
   或者换一个装了这个包的解释器。也可以直接用第四节「接入我的 IDE」，
   在你本来就能跑的环境里跑。

Q: 代码跑完了，但我想再看一遍过程？
   底部时间轴拖到最左，点 ⏯ 从第一帧开始重放；
   或点 ⏭ 一格一格看。

Q: 代码里有联网 / 删文件等危险操作，担心被真的执行？
   「运行」按钮（子进程模式）默认开着护栏：拦截联网、越界写盘、子进程，
   界面会提示。要真实环境就用「接入我的 IDE」—— 探针只旁观，不拦任何东西，
   所以那种代码请在自己可控的环境里跑。

Q: 结果里的值和我想的不一样？
   先看变量卡片上是否标注「占位」—— 那说明本机缺这个包，值不可信；
   「接入我的 IDE」或装好依赖后重跑即可得到真实结果。
